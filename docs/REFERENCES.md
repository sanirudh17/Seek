# Reference decisions (Stage 1)

Read on 2026-10-11; these projects are references, not Seek measurements.

- [fsearch](https://github.com/noahdunnagan/fsearch) and [crossplatform fork](https://github.com/threehymns/fsearch-crossplatform): preserve the flat, mmap-able directory-subtree index, name interning, masks, parser, matcher, ranking and live overlay. Vendoring candidate is `16eaebd89b8db161e4a5cac961f746565b878686`, MIT, copyright Noah Dunnagan and threehymns. The Unix socket and content search do not belong in Seek v1.
- [Windows PR #1](https://github.com/noahdunnagan/fsearch/pull/1): directory crawling is the helper-absent path; NTFS MFT/USN belongs to Stage 2.
- [wsearch baseline](https://github.com/andrewcoul/wsearch/blob/main/docs/benchmarks/2026-10-09.md): avoid per-entry regex allocations, deserialized object indexes, query debounce, polling and timer rescans. Its workload and memory measure cannot be directly compared with Seek.
- [FinderSearch method](https://github.com/zeusinsight/FinderSearch/blob/main/docs/benchmarks/README.md): 10,000 files, three unique exact target queries, folder scope, three warmups, 30 samples, median and nearest-rank p95, check results each time. Seek must label backend-only and painted end-to-end measurements separately; the reference's socket measurements include IPC.
- [OmniSearch](https://github.com/Eul45/omni-search): reference for raw MFT/USN and file-reference parent resolution. Seek keeps elevation in an optional helper, not the app.
- [Zeron](https://github.com/zeronsh/zeron): latest checkout uses a custom GPUI fork. Seek instead pins the requested Zed repository.
- [Zed](https://github.com/zed-industries/zed/tree/279fe070bb389b79652e52065b2f001edcc0b11b/crates/gpui): final pin is `279fe070bb389b79652e52065b2f001edcc0b11b`, dated 2026-10-04, with GPUI 0.2.2 and its separate Windows platform crate. Windows exports `Blurred`, `MicaBackdrop` and `MicaAltBackdrop`. Acrylic and window close were exercised locally; automatic fallback remains unverified.
- [gpui-component / GPUI Kit](https://github.com/longbridge/gpui-kit/tree/1ccf011620da24d633f7cd6d3c11ca2e97798dcf): 0.7.1 was the latest stable crates.io version when checked on 2026-10-11. The kit's GPUI snapshot metadata names the official Zed revision above. Four kit crates are vendored to align their dependency aliases with official git GPUI; changes are listed in `vendor/gpui-component/SEEK-PATCHES.md`. This combination compiled and ran on Windows.
- [Windows VSync source at the final pin](https://github.com/zed-industries/zed/blob/279fe070bb389b79652e52065b2f001edcc0b11b/crates/gpui_windows/src/platform.rs#L433): its VSync thread unconditionally invalidates every window on each cycle. Current upstream main was also read on 2026-10-11 and retains this loop. Continuation replaces this Windows crate through a documented local source patch at the same baseline, implementing the core's existing frame-waker hooks and parking VSync at idle. No upstream message/PR was sent. See `vendor/gpui-windows/SEEK-PATCHES.md` and the measured report.
- [usn-journal-rs](https://github.com/wangfu91/usn-journal-rs): inspected `d811c0647ad10c66dcea0a41ca7897c39a95c87a`, version 0.5.0, latest commit 2026-10-10. Active recent changes are evidence of current maintenance; no dependency added before Stage 2. Its examples explicitly require administrator privileges.
