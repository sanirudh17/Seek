# Shape — preview failure and recovery (item 1.2)

Operate/Read. The person selecting a local document needs a dependable preview and an explanation when it cannot load. Preserve the current PDF raster and Word presentation; no new reader layout is part of this reliability item.

- Keep one stable loading/error canvas, existing page navigation and user-driven Retry. Show the real worker error in readable body text rather than hiding it only in a tooltip.
- Add a secondary Copy diagnostics button, keyboard accessible, using existing controls and palette. Copying is explicit and local; never upload document names/content/logs automatically.
- Distinguish cold allowance, normal request deadline, cancellation, mismatched host, native failure and over-limit input. One automatic retry is finite; switching selection cancels prior work.
- Diagnostic logs rotate and record host/native/file/result stages and version/protocol. No idle timer/thread is introduced for logging. An unwritable log must not make an otherwise valid preview fail; memory diagnostics explain that condition.
- Verify normal/enlarged pixels and paging, invalid files, mismatched/missing protocol, retry/cancel/rotation, host startup timing and the visible error actions. Do not claim the multi-day incident is reproduced unless evidence establishes it.
