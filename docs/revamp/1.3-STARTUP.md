# 1.3 Startup visibility

The native backend previously called SetWindowPlacement with a visible show command before the app factory applied saved appearance or rendered a scene. The class brush was already black. Initial placement now remains hidden; an explicit queued initial draw handles Windows not issuing WM_PAINT for hidden windows. Dark mode and backdrop are applied before that draw, and successful renderer presentation gates showing/activation. Maximized placement uses its final show command directly. Seek content fades from 88% to full opacity over 120 ms when Windows client animations are enabled. Carbon was not changed; its possible equivalent ordering issue needs a separate investigation.

Validation: debug+benchmarks build, 77 app tests (5 ignored), strict all-target/all-feature Clippy. Owned native windows launched/closed normally for dark glass, dark opaque, light opaque and saved-maximized. Trace ordering was saved appearance, successful hidden draw, reveal in all four. A 500 ms delayed factory remained hidden for 100 native observations before reveal. Evidence: .references/item-1.3-startup.json. No production profile was used.

Raw observations are not matched performance comparisons: published optimized baseline visible at 550.7 ms; new debug opaque dark 916.9 ms, light 744.6 ms, maximized 523.8 ms; the artificial-delay sample 2414.0 ms. Cold caches were not controlled. Process-entry overhead varied. Quiet CPU sample was 296.875 ms over 20 seconds, not zero; foreground was not held, so idle acceptance remains outstanding. Captures were occluded by another foreground app and are invalid as visual flash evidence. Physical scanout, high-speed transition recording, disabled-animation visual inspection and device-loss at first present remain unverified.

## Native critique

The entrance is short, changes opacity only, and does not delay input. The first draw is explicitly requested once; there is no new idle polling. Keep backdrop policy in one backend for the next item. Native trace checks support ordering, not a claim that every DWM/driver transition is visually flawless. Questions skipped: native Windows assessment A only; web detector and web route checks do not apply.
