# Minimize material and default-view control refinement

User reported a pale frame only during native minimize, from restored and maximized windows. The visible-material WM_NCACTIVATE guard excluded IsIconic windows, even though Windows can set that state before finishing the minimize animation. Keep the existing material-active non-client handling for all visible glass windows, including iconic ones. Continue forwarding to DefWindowProc and leave WM_ACTIVATE focus/accessibility behavior untouched. No timer, material replacement, forced animation disabling or tint change is introduced.

This is a targeted correction to a plausible transition ordering defect. Build/lint/tests support correctness; high-speed visual acceptance across DWM/driver states remains open. Do not equate a settled screenshot with proof of no transient pale frame. Microsoft reference: https://learn.microsoft.com/en-us/windows/win32/gdi/nonclient-area.

Settings > Files and search > Default view now uses separate 36 px rounded text-only buttons with quiet borders, an explicit selected state, 8 px gaps and no outer segmented frame. Icons are removed only from these choices; approved navigation/toolbar icons remain.

Evidence: .references/minimize-polish-clippy.log, minimize-polish-tests.log and minimize-polish-build.log. Review in the next isolated build; production data is unchanged.
