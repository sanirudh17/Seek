# 1.5 - details-only presentations

Removed PresentationML parsing, saved slide images, presentation thumbnail-host rendering, slide text/paging, and their renderer tests. Presentation extensions ppt/pptx/pptm/pps/ppsx/ppsm/pot/potx/potm/ppam/sldx/sldm/odp show normal metadata/association artwork with standard double-click/Enter opening. It delegates to the normal Windows file association and performs no Office automation or conversion. Unsupported files reached through the enlarged reader also show details only. A file type either previews correctly or shows details.

PDF raster/session/cache behavior is unchanged. Word retains its existing text/thumbnail fallback. Preview controls use Page labels only. Historical release reports describe the old shipped implementation; the current README and preview follow-up mark presentation support as removed.

Validation: debug build, 79 regular app tests (4 ignored), and strict all-target/all-feature Clippy passed. A new routing guard covers all presentation extensions including uppercase and confirms PDF/DOCX/XLSX still route to the host. Native owned fixtures checked 13 presentation types: Open in PowerPoint was present, Enlarge/loading/error previews were absent, and no host log was created before switching to PDF. PDF page 1 and page 2 rendered. Word fixture text was present in the accessibility tree; a harness assertion initially expected the wrong phrase. Further enlarged Word/tab automation was interrupted by concurrent user Settings navigation and is unverified. The Open action's OS association handoff was not invoked against invalid fixtures. No real documents were modified.

Latest user refinement: removed the dedicated Open in PowerPoint buttons from the panel and enlarged reader. Standard double-click/Enter and the normal context-menu Open command remain consistent with other file types. Earlier native checks above validated the prior explicit-button design; the latest button removal is a separate follow-up.

Duplicate-button follow-up verification: rebuilt successfully; the presentation host-routing guard and strict all-target/all-feature Clippy passed. A fresh GUI attempt was blocked by window_not_focused before pointer input was sent, so the latest absence-of-buttons runtime assertion remains unverified. No forced foreground retry was attempted.
