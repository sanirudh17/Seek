# 1.6 - search folder activation (GUI acceptance pending)

Source tracing confirmed that list double-click, grid double-click and Enter used open_selected, which always sent Command::Open to the backend. Folder results therefore opened externally. The shared route now receives the current Window, distinguishes directory rows and enters them through scope_to in the current tab. Files and explicit Reveal retain their existing shell routes. The existing Ctrl+Enter path opens the selected folder in a new tab. scope_to remembers the current search before clearing it, allowing Back/Forward to restore the search and entered folder.

The context-menu folder Open already used scope_to; it now also benefits from history capture. Directory rows ending in a presentation extension remain folders in the information panel.

Validation: debug build, 79 regular app tests (4 ignored), and strict all-target/all-feature Clippy passed. Runtime double-click/Enter, Ctrl+Enter and Back/Forward acceptance is unverified: concurrent user navigation into Settings interrupted the isolated desktop sequence. This item is in progress and is not marked done. No files were written by the navigation change.
