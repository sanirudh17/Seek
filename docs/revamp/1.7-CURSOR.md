# Windows grab cursor - item 1.7 follow-up

Confirmed source cause: util.rs load_cursor matched PointingHand/DragLink but omitted OpenHand/ClosedHand; both fell through to IDC_ARROW. Map the two grab styles to IDC_HAND. This uses Windows' native hand and accessibility appearance; Windows supplies one shared resource rather than separate open/fist artwork. No GPUI upgrade or synthetic cursor image.

The production app builds. A regression test asserts non-null shared hand handles and distinguishes the arrow handle. Standalone vendor tests without test-support hit the existing render_to_image trait feature mismatch. Enabling the correct GPUI test-support feature was blocked by an uncached pinned proptest Git dependency in offline mode, so this vendor test has not executed. Actual cursor appearance remains a GUI acceptance item.
