# Original image pixels in Quick Look

The enlarged image request now decodes the source image on the existing worker instead of asking Windows for another bounded thumbnail. It preserves original dimensions, applies EXIF orientation and converts straight RGBA to GPUI's premultiplied BGRA. Fit and 100% therefore operate on actual source pixels when decoding succeeds. Existing pinned image codecs already enable the common formats through GPUI; no dependency or GPUI upgrade was introduced.

The footer identifies original dimensions, loading an original, or preview-only resolution. Unsupported/unavailable or oversized sources retain their existing bounded preview with an explicit resolution label. Original input is capped at 64 MiB, decoded dimensions at 8,192 per axis and 24 million pixels, and the decoder allocation request at 128 MiB. The axis bound avoids submitting arbitrarily wide/tall textures to the GPU. These limits do not claim arbitrary codec execution is preemptible: cancellation is checked before decoding, between stages and during pixel conversion, and obsolete replies remain rejected by the worker generation.

The cache permits one original-image allocation above its normal 32 MiB LRU budget; it does not immediately evict a valid original merely because it is larger than a thumbnail. The allowance is the largest original entry, rather than the sum of all original entries. Selection/Quick Look changes retire inactive previews through the existing GPU-release path. No idle decoding timer was added.

The owned-image test verifies 2400×1400 source dimensions, premultiplied alpha/channel order, EXIF-rotated JPEG dimensions, oversized-axis refusal, cancellation and cache residency/retirement. Native 100%/Fit/pan and memory/idle acceptance remains in the final combined checkpoint.
