# Text, code and Markdown - item 2.3 shape

Native Operate/Read refinement. Keep the approved Quick Look shell and keyboard focus rules. Text/code use a selectable editor with line numbers and Find; Markdown offers rendered Read and Source. Editing is explicit, with Save, Revert and clear dirty state. Keep content in the readable middle of the available viewport, with existing native controls and typography. Load local, embedded and HTTP(S) Markdown images, following the user refinement. Resolve relative image paths against the opened document; never execute scripts.

Read/load/save run off the UI thread. Editing must preserve a known lossless encoding, BOM and consistent line endings; binary, truncated, unavailable, linked or ambiguous inputs stay read-only with an explanation. Keep a complete expected byte snapshot, detect external changes, stage in the same folder and flush before atomic replacement, preserving a recoverable original. Handle save failures and concurrent changes explicitly. Never overwrite a changed file silently. Test encoding/EOL round trips, truncation/binary/reparse boundaries, conflict, failed replacement and undo before exposing Save.

Existing GPUI editor/find/rich-text facilities are preferred; no GPUI upgrade. Syntax support must be explicit, with plain-text fallback for unknown languages. Markdown task edits are ordinary buffered edits and use the same save/conflict path.
