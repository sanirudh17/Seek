# 2.3 - Native text reader and safe editing

Implemented locally on revamp/glass-quicklook-panes; no release or version change.

## Behavior

Quick Look uses a native selectable, scrollable reader/editor for text and code, with line numbers, basic lexical syntax highlighting, and Find. Markdown has Read/Source modes, rendered local/embedded/HTTP(S) images and buffered task checkbox changes. This is basic lexical highlighting, not compiler or tree-sitter analysis. Unknown languages remain plain text.

Read/Source form one compact control group; Find, Edit/Save and More form the next. More contains undo saved change, discard draft and finish editing. The footer shows encoding/line endings; the toolbar shows save status. Text editing has its own Settings page with Auto-save and Keep backups (both default off). Auto-save debounces edits for one second, waits for IME composition, and pauses on conflicts/errors. Disabling backup retention still preserves a session undo snapshot; failed saves retain recovery copies.

Space closes read-only previews but types in editing/Find. Escape first closes Find, then closes Quick Look; unsaved edits offer Save and close, Discard and close, Keep editing. Finish editing closes Find and restores reader focus. Escape during a save requests closure after success; newer drafts and failed saves remain protected. The obsolete Close preview tooltip was removed. The inspector now renders a compact readable Markdown/text excerpt instead of the generic framed Shell icon.

## Black-window correction

Atomic replacement can momentarily remove a file from index results. Previously this erased the selection driving Quick Look while the browser remained hidden, producing an empty black surface and orphaned editor focus. Quick Look now pins its opened row independently of result refreshes. Closing moves focus to the browser before disposing reader state. Missing-file fallback always offers a visible close action.

## File correctness

Complete editable documents are limited to 2 MiB/50,000 lines. Preserve known lossless UTF-8/16/32 BOM forms and consistent LF/CRLF/CR. Binary, mixed endings, unknown encoding, truncation, links, cloud placeholders and multiple hard links are read-only. Saves compare the expected bytes, stage and flush beside the original, use ReplaceFileW, verify the result and retain recovery on failure. External changes are never silently overwritten. Undo uses the same guarded path.

Remote images use bounded background WinHTTP GET with system TLS/proxy, HTTP(S) only, redirects/timeouts and a 16 MiB body ceiling. Data images retain stable cached image identities. No Markdown script execution is introduced.

## Latest visual refinement

File columns now fill the available results width in restored/maximized windows, including inspector/sidebar changes. Filenames receive the largest extra share; date, size, type and optional folder columns retain readable minimum widths. Manual column sizes are retained until the viewport or column set changes. Content matching lines retain their wider minimum. Narrow windows scroll horizontally rather than compressing metadata to illegibility.

Find input is 36 px high. Default view choices use spaced icon-and-label controls with List, Icons and Gallery from the existing icon system. Text editing uses the existing document/script icon instead of the standalone pencil.

## Evidence and limits

The full app suite passed 104 tests (4 ignored), including encoding/EOL round trips, concurrent-edit conflicts, failed replacement, backup-off cleanup/session undo, task parsing, image sources and loopback HTTP redirect/body limits. Strict all-target/all-feature lint and native debug build are recorded in .references/layout-refinements-*.log. The initial Windows settings lock timing failure was addressed by extending the bounded background retry window; subsequent full suites passed.

The earlier owned review profile recorded successful automatic Markdown/code saves and undo without retained .bak files or a black reader. The latest column/Find/control refinements need user visual acceptance at restored/maximized sizes. Controlled idle CPU, high contrast and comprehensive keyboard/accessibility acceptance remain open; this checkpoint does not complete the entire revamp plan.
