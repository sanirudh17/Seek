# Copy, recycle redo and multi-item move continuation

Local phase-two continuation, version 1.0.2. No publication or production-profile changes.

Copy undo recycles only verified fresh destinations. Redo restores those same copied objects through the Recycle Bin provider, preserving their copied version even if their source has since changed. Existing or overwritten destinations without a fresh whole-root proof are not eligible. Directory snapshots include descendant identities, normalized contents and named streams. Windows reports the creation of copied directories before copying their children; their final proof is therefore appended at FinishOperations, with journal space reserved before mutation.

Move undo/redo supports multiple verified roots. Every source fingerprint and destination is checked before the first root moves. Source handles and stable parent chains remain held through execution. Subsequent native failures or cancellation may still leave completed roots; those outcomes stay recorded rather than being silently rolled back. Descendant callbacks must map to the same relative paths under a verified root. Same-volume inverses retain no-replace handle renames. Cross-volume inverses use guarded Shell moves and record actual outcomes, but this machine has only C: and no genuine second-volume acceptance has been performed.

Recycle redo validates restored objects before recycling again. Put Back obtains the actual restored path from the held object handle, including provider-selected keep-both names. It does not modify private Recycle Bin metadata.

History checksum verification uses the original serialized event before applying new optional-field defaults. This preserves older record chains when new snapshot fields are absent. An explicit legacy-record regression covers that boundary.

## Grouping and interrupted review continuation

New Folder with Selection is available from File actions and the command palette. It requires a common source parent, validates all selected snapshots before creating the new folder, uses create-new directory semantics and records no-replace item moves. Undo returns the selected items while retaining the folder, preserving anything subsequently added there. The name sheet states that behavior. A missing source or existing folder stops the action before moving selected items. Completed stages remain individually recorded if a later native failure interrupts grouping.

History now offers an explicit Review interrupted action. It rechecks recorded final fingerprints, distinguishes a matching result from missing/changed/unavailable data, and marks unmatched intentions as unknown. This read-only reconciliation neither changes the journal nor authorizes inverses for interrupted work. A crash between mutation and its completion record therefore remains unknown rather than becoming a guessed success.
