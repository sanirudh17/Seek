# Recorded Recycle Bin Put Back

Phase 2.5 continuation in the isolated worktree. Version stays 1.0.2; no push or release. Approved styling and native window behavior are unchanged.

## Behavior

History offers Put Back for eligible recycle operations, including older operations. File actions and Ctrl+K offer Put Back last recycled items. The shared Undo last operation action, including file-list Ctrl+Z, invokes Put Back when recycling is the latest eligible mutation; it does not skip later work. Redo recycling is not yet offered. Reader/editor undo remains separate.

Only actual successful Windows recycle outcomes are candidates. Before recycling, the worker captures the regular file's volume/file ID, byte length and primary-stream SHA-256. The recycled destination must match that fingerprint after completion. Put Back requires this recorded identity, an unambiguous recycled physical path and a valid original filename. Existing journals without that evidence are not granted inferred eligibility.

The operation worker locates the exact physical object through the Recycle Bin namespace. It never chooses an item merely by its original filename: the same filename can have several different recycled versions. Restore uses the namespace item's canonical undelete verb, with its window owned by Seek. Windows exclusively owns its private Recycle Bin metadata; Seek never edits or deletes those metadata files.

Before invoking Restore, every item is checked. The original parent and recycled parent chains must be local, available and free of links; directory identities remain held without delete sharing. Recycled file handles retain read access without write sharing through execution and must match the original snapshot. Existing original destinations reject the request before any item in the batch is restored. Missing original folders are not recreated silently. Source disappearance, replacement or changed content refuses restoration.

A collision that appears after preflight is handled by the Windows Restore provider's native confirmation UI; this is not an atomic no-replacement rename guarantee. Seek does not silently authorize replacement. If the provider cancels, runs asynchronously, or restores somewhere other than the original location, the operation is not reported as confirmed success. The error directs the user to review the bin and history. It does not guess a destination or replay the operation. Normal successful completion is independently verified against the exact original fingerprint and disappearance of the recycled data object.

Each item has durable Before/After evidence. A completed restore consumes the original recycled identity immediately, including across restart, even if the outer job was interrupted afterward. Interrupted operations are never replayed automatically. Failed requests that made no change can be retried after the conflict is resolved. Focus moves to the stable History or browser control before a completed restore removes its Put Back button.

## Current bounds

This increment supports confirmed local regular files up to 16 MiB with representable valid original filenames. All successfully recycled items in the candidate job must have eligible snapshots; an unsupported item prevents offering a misleading partial inverse. Failed items that were never recycled are not restored. External empty-bin/restore actions can make a previously eligible record unavailable; execution revalidates it and returns an error without changing another item.

Directory and larger-file Put Back, copy/directory/cross-volume undo, redo recycling, journal retention/reconciliation and broader conflict/progress acceptance remain pending. Phase 2.5 is still partial. This is not a claim of completing the original revamp checklist.

## Evidence

Four native STA integration tests use disposable owned files:

- Exact file restore preserves bytes and identity, removes the object from the Recycle Bin namespace, consumes its history eligibility and refuses a second restore.
- Two successive recycled versions of the same original name remain distinct. Restoring one preserves the other. An occupied original name refuses the second restore without overwriting either file, then permits retry.
- A collision on one batch member preserves every recycled member before mutation; retry restores both originals after the collision is handled.
- Put Back evidence survives worker restart. Missing original parents and modified recycled contents refuse restoration; correcting those conditions permits retry.

An exploratory assertion about physical $I metadata deletion was rejected: private metadata-file retention is not a public Restore contract. Final tests check the provider's visible namespace and the exact restored identity instead. Windows metadata is not manually cleaned by the app or tests. This follows the canonical provider contract rather than treating a raw filesystem move as Restore.

The full suite passed 134 tests (4 ignored), strict all-target/all-feature offline Clippy passed with warnings denied, and the benchmark-feature debug build passed. Logs: .references/put-back-final-{tests,clippy,build}.log. The small History/menu/palette additions reuse existing controls; no new GUI review launch was requested. Their visual acceptance remains part of the next bundled checkpoint.
