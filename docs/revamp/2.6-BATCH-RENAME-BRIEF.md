# Batch rename shape

Keep the existing native name sheet and approved type, surfaces and controls. Batch rename is an explicit multi-selection action, with replace and numbered-name modes. Show original and proposed names together before applying. Keep extensions by default in numbered mode. Display duplicate, occupied and invalid destinations inline; apply only a complete conflict-free selection or explicitly skip conflicting rows. Never overwrite.

The worker must revalidate all names, identities and destinations before its first rename. Use unique same-directory staging names for swaps and cycles, record each actual native rename in the existing journal and retain original-to-final object mappings for inverse operations. If staging or finalization fails or is cancelled, attempt no-replace rollback and report each outcome; a failed rollback must preserve evidence and identify the remaining staged files. Never promise filesystem transactions or rollback when an external actor blocks restoration. Reopen/restart must preserve interrupted evidence without retrying it automatically. Tests use owned files for duplicate names, existing destinations, Unicode, case-only changes, swaps/cycles, failure/rollback, cancellation and restart.
