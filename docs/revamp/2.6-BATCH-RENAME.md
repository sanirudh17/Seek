# Batch rename implementation

File actions and Ctrl+K now expose Batch rename. The name sheet offers case-sensitive text replacement or numbered names (three-digit minimum, configurable starting number, file extensions retained). Original and proposed names appear together. Preview runs after a short event-driven debounce on the background executor; revision and input-entity checks prevent stale work from updating another sheet. No preview timer runs while idle. A batch is limited to 1,000 selected items from one folder.

Duplicate, occupied, unavailable and invalid targets block Apply. Skip conflicting items is explicit, and dependencies on skipped sources are also blocked. Empty/no-op proposals do not apply. The worker rechecks source snapshots and every destination before its first change. It holds source handles and stable parent chains and uses unique same-directory stages to support swaps and case-only changes without replacement. Completed native moves are durably recorded, including staging and rollback. Batch undo/redo collapses each verified object's recorded path chain into its original/final mapping; interrupted or failed batches are not granted an inferred inverse.

Cancellation or a later failure triggers best-effort, identity-checked, no-replace rollback. If an external collision blocks rollback, the external file is preserved and the remaining stage paths are reported. A mutation whose After append fails is tracked by live object identity rather than falsely treated as unchanged. This is recoverable staging, not a filesystem transaction.

The existing name sheet also now traps Tab within its controls and gives Escape a single cancellation route. Batch fields retain ordinary cursor navigation; Enter activates Apply only from a text field or Apply itself, leaving mode controls their own activation.
