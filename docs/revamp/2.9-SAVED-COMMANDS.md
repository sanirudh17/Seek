# Saved commands

A dedicated settings page manages up to 32 commands with a name, full .exe path, arguments (one per line), optional absolute working directory and selection requirement: none, one or one-or-more. It offers edit, remove and clear-form actions. Saving or editing never executes a command.

Ctrl+K exposes explicit Run actions; contextual menus link to Jump rather than duplicating every saved command. Disabled commands lack their required context; invocation rechecks a stale selection. Saving never runs a program. Invocation captures selected paths and starts the process on the background executor. A persistent result sheet reports running PID, actual exit status, bounded stdout/stderr and copyable output. Each stream keeps at most 32 KiB but drains excess to avoid filling a pipe. At most four commands run concurrently. Closing the result sheet leaves the program running; a revision token prevents old completion from reviving a closed or replaced sheet. Output stays in memory. Console windows are suppressed; graphical programs retain their own windows.

The aligned form has a compact arguments editor with one argument per line, separate token help and five inline footer controls. A program-window/play outline identifies Saved commands.

Arguments remain separate through std::process::Command. There is no implicit shell or environment expansion; batch/script files are not accepted as executable programs. {file}, {name} and {folder} support single-context substitutions, while {files} must occupy a whole argument and expands into separate path arguments. Double braces produce literal braces. Standalone path arguments retain their original Windows characters, including non-Unicode names; embedding an unrepresentable name is refused. Validation bounds templates and the expanded Windows command line, rejects NUL and unknown placeholders, and enforces the selection requirement at invocation. A user explicitly choosing an interpreter executable remains responsible for that interpreter's own argument language.
