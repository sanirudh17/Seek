# Split panes: first implementation batch

Native Operate surface, preserving Figtree, Hugeicons, neutral glass, existing file operations and system animations. Impeccable/Taste app-screen guidance applies; the pinned GPUI brief supersedes web generators. No approval launch is requested.

The present shell owns one result-generation counter and one active browser. Duplicating the visual table would share mutable routing and allow late results or file commands to affect the wrong pane. First establish stable pane/tab/split identities, a bounded layout tree, independent tab sessions, safe moves/closure, divider geometry and per-pane request stamps. Persist only navigation state, never cached results, dirty text drafts or executable work.

The first batch also restores the existing single-pane tab session across restart. Loading is bounded and versioned. Invalid/newer or multi-pane state must be preserved rather than silently flattened before the multi-pane renderer lands. Existing profiles with no session continue to start as before. Writes stay off the UI thread and coalesce only after changes; no idle timer.

Next batch binds independent browser controllers to layout leaves, then wires pane splitting/closing/focus/Alt+F5, divider dragging and tab/file transfers. Only then may split controls become available. Drag-to-split animation remains 3.2. This first batch is not represented as a working multi-pane UI.

Acceptance: adversarial persisted state, duplicate/dangling IDs, bounds and size limits; independent navigation snapshots; failed moves leave the full model unchanged; last-tab moves collapse their source safely; divider rectangles never overlap or violate minimums; late replies for one pane never become valid after another pane activates. Run app regression/lint/build without launching the app, per the user's current instruction.
